# 评审模拟清单

用于 P6：以评委视角挑错。**只出意见，不直接改稿**——改稿是人的事。
产出写进 `review.md`，结论必须能回答一个问题：**这篇现在交，会死在哪。**

## 一、评阅关注点（经验权重，非官方）

| 维度 | 评委实际在找什么 | 印象权重 | 常见失分 |
|---|---|---|---|
| 摘要 | 每问的答案在不在、有没有数字 | ★★★★★ | "建立了模型并求解"，无结论数字 |
| 问题分析 | 有没有真读懂题、思路自洽 | ★★★★ | 复述题目、无技术路线 |
| 模型假设 | 每条有没有理由 | ★★★ | 堆假设、与模型矛盾 |
| 模型建立 | 式子有没有含义、是否适配 | ★★★★★ | 套模板、变量定义混乱 |
| 求解 | 算法可行、参数合理 | ★★★★ | 只有伪代码、无收敛说明 |
| 结果 | 有没有解释、是否合理 | ★★★★★ | 只堆表、数字与正文/代码矛盾 |
| 检验 | 灵敏度/稳健性真做了没 | ★★★★ | 一句话带过、无数据 |
| 创新性 | 有没有一个非模板的点 | ★★★ | 全文标准套路 |
| 写作 | 逻辑、术语、图表 | ★★★ | 口语化、图表未引用 |
| 格式 | 页数、编号、参考文献、附录 | ★★（但触发即否决） | 超页、缺源码、身份泄漏 |

**结论**：摘要 + 结果 + 建模 三项占了大半印象分。时间不够就先打磨这三块。

## 二、国一论文的共同特征（拿来自检）

- [ ] 摘要能在 60 秒内说清"做了什么 / 怎么做的 / 结果多少 / 为什么可信"
- [ ] 每问都有**一个**清晰的建模视角，不是方法大杂烩
- [ ] 至少有一个"非模板"的处理（特殊约束的转化、指标构造、算法改进）
- [ ] 有技术路线图，各问依赖关系一眼看清
- [ ] 结果有**解释**：这个数字意味着什么、和常识对不对得上
- [ ] 灵敏度分析有数值、有结论（"参数 ±20% 时结论不变"也是结论）
- [ ] 模型评价的缺点写得具体、可信，不像客套
- [ ] 图表黑白可读、单位齐全、全部被正文引用
- [ ] 附录代码能跑、有注释、和正文数字对得上
- [ ] 全文没有身份信息、没有编造文献

## 三、一票否决级硬伤（发现即最高优先级）

- [ ] 全文核心段由 AI 生成、未标注，或缺《AI 工具使用详情》PDF
- [ ] 核心建模完全没有人工参与痕迹（`changes.md` 空或无实质条目）
- [ ] 编造参考文献、数据或实验结果
- [ ] 摘要缺失或超过一页
- [ ] 正文超过 20 页 / 出现学校、队号、赛区信息
- [ ] 附录代码无法运行，或运行结果与正文不符
- [ ] 问 A 答 B（模型与题目要求明显不匹配）

## 四、10 分钟抽查动作

1. 只读摘要：能否说出做了什么、结果多少？不能 → 摘要不及格。
2. 从 `facts.json` 随机抽 3 个数，在正文找，是否一致？
3. 从正文随机抽 3 个符号，在符号表找，含义是否一致？
4. 抽 1 张图：正文引用了吗？单位齐吗？黑白能看清吗？
5. 看检验一节：有没有具体参数扰动和数值？
6. 翻附录：跑主脚本，结果能否复现？
7. `check.py --strict` 与 `layout.py` 是否 PASS？

## 五、输出格式（`review.md`）

```markdown
## 总体判断
（现在交会死在哪 / 距可提交还差什么）

## 最可能被扣分的 5 处
1. 位置（章节/图表号）+ 问题 + 建议改法
...

## 逐维度打分
| 维度 | 自评 | 依据 |
|---|---|---|

## 剩余人工 TODO
- [ ] ...

## 审核签字
- 审核人：____  日期：____  结论：□ 通过  □ 修改后再审
```

签字栏必须由人填；AI 只留空。
