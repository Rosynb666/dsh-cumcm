# 论文结构与格式（以 2025 官方规范为准）

> 依据：《2025 年全国大学生数学建模竞赛论文格式规范（2025 年修订稿）》
> https://www.cmathc.org.cn/mcm/tz/303.html
> 规则每年可能微调，**赛前必读当年官方文件**；本文件与官方冲突时以官方为准，并在 `review.md` 记差异。

## 一、硬性规定（电子版 = 实际提交物）

| 项 | 规定 | 对应实现 |
|---|---|---|
| 纸张 | A4，上下左右各留 **≥2.5 cm** 页边距 | `\geometry{margin=2.5cm}` |
| 第一页 | **摘要专用页**（电子版不含承诺书、编号页） | 模板首页即标题+摘要+关键词 |
| 摘要 | 含标题与关键词，**不超过 1 页** | 450–600 字，超页即删 |
| 页码 | **从摘要页开始**，页脚居中，阿拉伯数字从 1 连续编号 | `\pagestyle{plain}` + `\pagenumbering{arabic}` |
| 目录 | **不要目录** | 模板不提供，`layout.py` 会拦 |
| 正文 | 从摘要页之后开始，**尽量控制在 20 页以内** | 正文页数预算见第四节 |
| 附录 | 页数不限，必须含**支撑材料文件列表 + 全部完整可运行源码** | 模板附录 A/B |
| 身份信息 | 摘要页、正文、附录**任何地方**不得出现姓名/学校/赛区/队号 | `layout.py` 关键词扫描 |
| 参考文献 | 按科技论文规范，正文引用处标注 | `thebibliography` + `\cite` |
| 文件 | 单独 PDF（或 Word），**≤20 MB**，不压缩 | 编译后核对体积 |
| 支撑材料 | RAR/ZIP，≤20 MB，清单写进附录 | `支撑材料/` 目录 |

**一票否决项**：附录缺源码、源码跑不出论文结果、支撑材料与正文对不上、身份信息泄漏、AI 使用不合规。

## 二、结构顺序（照抄）

```
① 摘要页（标题 + 摘 要 + 关键词）          1 页，页码 1
② 一、问题重述                            0.5–1 页
③ 二、问题分析（含技术路线图）             1.5–2 页
④ 三、模型假设                            0.5 页
⑤ 四、符号说明                            0.5 页
⑥ 五、模型建立与求解（按问分节）            8–10 页
⑦ 六、模型检验（灵敏度 / 稳健性 / 误差）     1.5–2 页
⑧ 七、模型评价与推广                       1 页
⑨ 参考文献                                0.5 页
⑩ AI 使用声明                             0.3 页
⑪ 附录 A 支撑材料文件列表 / 附录 B 程序代码  不限页
```

正文（②–⑩）合计 ≤20 页。**不要目录**，不要承诺书。

## 三、排版参数（国一论文的常见长相）

- 正文中文宋体小四（12 pt），行距 1.5；英文与数字 Times New Roman。
- 论文题目：黑体三号居中；一级标题黑体四号；二级标题黑体小四；正文小四宋体。
- 页边距 2.5 cm；页码页脚居中。
- 公式：居中，编号右对齐，全文连续 `(1)(2)…`，**只给正文引用到的式子编号**。
- 图：图题在图**下方**，五号；表：表题在表**上方**。
- 表格一律三线表（`booktabs`），**不要竖线**，不要 Excel 网格线。
- 关键词 3–5 个，分号分隔。
- 全文图表建议 8–15 个，平均每 1.5 页一个；宁可少而精，不要堆图。

## 四、页数预算（20 页怎么分）

| 部分 | 页数 | 说明 |
|---|---|---|
| 摘要 | 1 | 超一页直接失分，宁短勿长 |
| 问题重述 + 分析 | 2.5 | 重述占 0.5，分析占 2（含技术路线图） |
| 假设 + 符号 | 1 | 假设 5–8 条，符号表 8–15 行 |
| 建模与求解 | 9 | 每问 2.5–3 页：模型 → 算法 → 结果 |
| 检验 | 2 | 灵敏度必做，稳健性选做 |
| 评价 + 参考文献 + 声明 | 2 | 评价要具体，别写空话 |
| 合计 | 17.5 | 留 2 页余量给超长公式与图表 |

附录不计入，但**别拿来藏正文**——评委知道该看哪。

## 五、各章写法

### 问题重述

用自己的话概括背景 + 逐条列出待解决的 n 个问题。**不得整段抄题**（查重与印象双失分）。
结尾用编号写清每问要交什么：一个数值？一套方案？一张表？

### 问题分析

每问四件事：目标 / 已知 / 缺什么 / 难在哪 → 打算怎么解。
必须有一张**技术路线图**（总体流程图），说明各问依赖关系与数据流。
解释为什么选这个思路而不是最热门的那个——评委最烦模板。

### 模型假设

格式固定：`假设 n：……。理由：……（数据/文献/简化必要）；放宽影响：……`。
5–8 条，宁少勿滥。与模型矛盾的假设比没有假设更糟。

### 符号说明

三线表：符号 | 含义 | 单位。按首次出现顺序排。
**全文符号以此表为唯一真值源**，后文不得改变含义。

### 模型建立与求解（主体）

每问三小节，缺一不可：

1. **建模**：变量、目标函数/方程组、约束，逐式解释物理或业务含义。
2. **求解**：算法选择理由、参数设置、复杂度或收敛性说明。
3. **结果**：表格 + 图 + 解释。解释回答"这说明什么"，不是复述数字。

### 模型检验

- **灵敏度**：改关键参数/权重，结论变不变（必做，至少一个）。
- **稳健性**：换方法、换样本、加噪声，结论是否一致。
- **误差/残差**：预测类必做。
- **常识对照**：结果与外行直觉、行业数据比一比。

### 模型评价与推广

优点要具体（"复杂度 O(n log n)，可实时"），缺点要诚实（"依赖平稳性假设"），推广给 1–2 个真实场景。

### 参考文献

- 只列真读过的；模型原始文献不确定时只写模型名。
- GB/T 7714 常见格式：
  - `[1] 作者. 题名[M]. 出版地: 出版社, 年.`
  - `[2] 作者. 题名[J]. 刊名, 年, 卷(期): 页码.`
- AI 工具条目单列，格式见 `references/compliance.md`。

### 附录

- **附录 A**：支撑材料文件列表（表：文件名 | 说明 | 用途）。
- **附录 B**：全部完整可运行源码，按问题分节，注明依赖与运行方式。
- 正文放不下的全量数据表、长推导。

## 六、摘要是唯一必读页

评委平均在一篇论文上花 3–5 分钟，**摘要决定进不进下一轮**。

结构（450–600 字，四段）：

1. 一句背景：什么问题，为什么值得做。
2. 逐问一段：方法/模型 → 关键步骤 → **具体结果（必须带数字）**。
3. 检验：做了什么，结论稳不稳。
4. 评价：优势 + 可推广性一句话。

硬性要求：

- 每问都要有**结论性数字**，不能只写"建立了模型并求解"。
- 能独立读懂，不依赖正文。
- 数字必须来自 `facts.json`（走 `\res{}`），与正文、附录一致。
- 不写"本文""我们认为"这类冗余主语，不用"很好地""有效地"。

## 七、写作红线

- 不用"显然""众所周知""大量实验表明"（除非有数据）。
- 不用第一人称"我"；用"本文"或客观陈述。
- 不堆没有数据支撑的形容词。
- 每段第一句是论点，后面是证据。
- 图表必须在正文被引用（"如图 3 所示"），否则删掉。
